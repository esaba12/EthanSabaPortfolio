## 3. Bugs and UX problems on the live site

- **Hydration error and photo dates one day early (P0, `/creative`).**
  `PhotoCarousel.tsx:174` renders `new Date(date).toLocaleDateString()`. An ISO date with no
  time is parsed as UTC, so US visitors see the previous day: `2023-06-24` displays as
  **6/23/2023** on the live site. The server and client also format it differently, which
  logs React error #418 (hydration mismatch) in the console on every load. To fix it,
  format the `YYYY-MM-DD` string directly instead of parsing it as a `Date`.
- **Play button covers the project title (P1).** All three home posters have their title
  centered, and the orange play button sits right on top of it ("Recr▶ting OS", "Ou▶tpost").
  Move the button to a corner or re-crop the posters.
- **Tag filter on the home page (P1).** There are 15 filter chips above only 3 cards. The
  filter is applied before the limit of 3, so clicking "Python" on the home page shows
  projects that aren't in the featured set. The tags also mix languages with product names
  (Claude, Demucs, Deno Edge Functions). Remove the filter from the home page and group
  tags on `/projects`.
- **Cards can only have one link (P1).** A card opens `repo || demo` in a new tab, so if it
  has both, the demo can never be reached. The card is a whole `role="button"` with a
  nested `<button>` (play) inside it, which is an a11y nesting problem. Also, "Click to view
  project" doesn't say where it goes. Use explicit "Live" and "Code" links instead.
- **Contact form (P2).** It uses `alert()` for success and errors, has no loading or
  disabled state (so it can be submitted twice), and shows no inline confirmation. The
  "Location" card is styled as a link with `href="#"`.
- **Footer alignment (P2).** The footer uses `container mx-auto max-w-6xl`. The pages use
  full-bleed `px-6 … xl:px-28` gutters, so the footer logo and copyright don't line up with
  the page content.
- **Content hidden until scrolled into view (P2).** Sections start at `opacity: 0` with GSAP
  `from` until they scroll into view. That's fine for real visitors, but full-page
  screenshot tools and some preview crawlers capture a blank Skills and Projects area.
- `ProjectsGrid` uses `text-gray-300` and `bg-gray-800` instead of the brand tokens (P2).

## 4. SEO, sharing and performance

- **Link previews are broken (P0).** `og:image` and `twitter:image` are `/logo.svg`.
  LinkedIn, X, iMessage and Slack don't render SVG previews, so sharing ethansaba.com shows
  no image. Add a 1200×630 PNG OG card, or generate one with `opengraph-image.tsx`.
- **Every page has the same title (P1):** "Ethan Saba - Computer Science Student &
  Developer". There is no per-route metadata. Most pages are `'use client'`, so metadata
  needs to go in a per-route `layout.tsx` or the pages need to be split into server and
  client parts.
- **No `robots.txt`, `sitemap.xml` or canonical URL (P1).** All return 404 or are absent.
  Next can generate them (`app/robots.ts`, `app/sitemap.ts`).
- **No analytics (P2).** There's no Vercel Analytics or Speed Insights, so you can't tell
  whether recruiters actually visit.
- **The logo is 438 KB (P1).** `logo.svg` and `favicon.svg` are each a 1024px PNG wrapped
  in an SVG. They load on every page (nav and footer). Re-export as a real vector or a
  small PNG/ICO.
- **Uncommitted photo recompression (P1).** Your working tree has `photo-1..5.webp`
  recompressed from about 1.3-1.8 MB down to about 270-380 KB, plus a `PhotoCarousel`
  preload refactor. Production still serves the large versions. Commit and deploy this.
